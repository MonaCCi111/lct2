Рома – фронтенд. Пакет dispatcher_integration_v1.

Если клонируешь весь репозиторий, большие Parquet подгружать не нужно:
фронтенду хватает файлов этой папки и ответов API v2 бэкенда.

Начни с ARCHITECTURE_V1.txt и api_contract_v1.json. Данные приходят
через /api/v2; Parquet и модели в браузер не передаются. docs содержит
описание полей, таймлайна и маршрут восьми сценариев для приёмки.
model_type_decisions.json показывает решения по всем 19 типам.

Экраны: обзор объектов и нагрузки, карточка объекта, мониторинг
каналов, список ситуаций, очередь групп с отдельными черновиками,
деталь черновика с исходными свидетельствами и графиком, решение
диспетчера, история пожаров и исторический таймлайн. Навигация всегда
сохраняет object_id, период, at, фильтр типа и идентификатор карточки.

При прогнозе показывай model_version, target_kind, горизонт, score и
ограничения. Баллы разных моделей не сравниваются как единый риск.
При наблюдаемом статусе score отсутствует; показывай исходный текст и
время. Не рисуй универсальный порог 0,7, условные значения статуса
0/0,7/1 или автоматически готовый текст наряда. Для каждого канала
показывай свежесть телеметрии, причину отсутствия прогноза и отдельное
состояние наблюдения. «Нет недавних событий» не окрашивай как поломку.

Пожарный раздел показывает отсутствие подтверждённого реестра;
число пожаров null. Дымовую статистику подпиши отдельно. ИТС null
показывай как «не рассчитан» с причиной. Газовый порог 1 об.% метана
не означает доказанную утечку; графика плановых работ пока нет.

В таймлайне отрисовывай только события до текущего seq/at. После seek
сбрось собранное состояние; не показывай будущий исход прогноза.
Решение approved/rejected требует написанную диспетчером причину;
успешный POST должен вернуть сохранённое решение. Не выдавай
SIMULATED_DISPATCHER_DECISION за реальное действие.

Приёмка: все восемь сценариев из docs/DEMO_ROUTE_V1.txt; обычная смена
без ложных карточек, насосный черновик, 31 черновик в одной группе,
массовый дым без наряда, газовый час, возврат записи канала и пиковый
день. API и UI должны совпадать по числу карточек, черновиков и групп.
Если бэкенд не реализовал конкретный endpoint v2, показывай явное
«раздел пока недоступен», а не выдуманные данные.
