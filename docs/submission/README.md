## Маршрут для жюри

1. Откройте обзор, затем очередь `/review`. В группе доступны отдельные черновики, источник сигнала, время и исходные свидетельства. Решение диспетчера сохраняется отдельно от создания наряда.
2. Откройте `/channels` и `/situations`. Каналы без пригодной модели остаются видимыми с причиной ограничения.
3. Откройте `/analytics` и `/fire-history`. Дымовые события показаны как статистика сигналов датчиков, без утверждения о подтверждённых пожарах.
4. Откройте `/replay`. Ползунок воспроизводит восемь проверенных исторических сценариев и скрывает события после выбранного момента.
5. Откройте `/api/v2/meta`: `data_source` должен быть `ml_handoff_parquet`. В Swagger по адресу `/docs` доступен контракт API.

Рабочая очередь использует модели состояния фазы и насоса, а также наблюдаемые статусы. Балл модели не равен вероятности физической аварии. Прототип работает на архиве до 30 июня 2026 года; живой поток, график ППР, журнал ремонтов и подтверждённый реестр пожаров заказчик пока не предоставил.

Решения диспетчера сохраняются с причиной, автором, временем и `draft_id`. По этому ключу ML-процесс может соединить их с версией модели, баллом и исходными показаниями для анализа качества очереди и подготовки следующей версии. Для обучения на физических отказах потребуются проверенные итоги работ. Автоматическое переобучение не включено.
