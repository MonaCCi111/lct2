Передача backend/frontend v1 – проверка 25.09.2026

Созданы две папки: integration/backend_sanya и integration/frontend_roma.
У них одинаковый hash api_contract_v1.json. В бэкенд-пакете 67 файлов
данных, моделей, реестров и документов, 108 640 760 байт до Git LFS.
Каждый файл записан в data/package_manifest.json с SHA256. Основные
14 ресурсов подтверждены по исходному schema_manifest.json.
Parquet отправляются через Git LFS; в обычном Git только указатели.
Исходные 2,6 ГБ годовых журналов не копируются: исторические экраны
работают по производным витринам и сохранённым свидетельствам.

Положительная проверка:
- все 67 файлов на месте, размер и SHA256 совпали;
- два модельных bundle прошли собственную проверку хэшей;
- восемь сценариев replay присутствуют;
- из переносимых шести входных таблиц за 01–03.10.2024 получены
  те же строки score, что из оригинального расположения: 110 фаза,
  65 насос; разница EXCEPT ALL в обе стороны равна нулю;
- в контракте есть отдельное решение по draft_id, нет суточного
  лимита 10, в демо нет выдуманной реальной обратной связи;
- frontend fixtures содержат реальные строки handoff, пожарное число
  и числовой ИТС не заменены нулями.

Границы:
- пакет исторический, дата отсечки 30.06.2026; новый поток и
  проверенный инкрементальный расчёт признаков не реализованы;
- произвольный полный график или replay вне восьми сценариев требует
  отдельного доступа к архиву исходных журналов или event store;
- frontend/backend пока не реализуют /api/v2; контракт задаёт работу,
  но её приёмка возможна после их изменений;
- нет реальных решений диспетчеров, подтверждённых пожаров и числового
  физического ИТС; график ППР от заказчика ещё не получен.
