Состояние фазы, power_phase_scada_v2

Общий интерфейс фазы и насосов описан в USAGE_ACTIVE.txt. Этот файл
сохраняет полный порядок воспроизведения фазовой ветки.

Проверенный runtime:
Python 3.12.14, DuckDB 1.5.5, pandas 3.0.1, LightGBM 4.6.0,
scikit-learn 1.7.2.

Запускать из корня G:\lct2\tmp\publish_ml. Исходные CSV организаторов
остаются в G:\lct2\dataset и не изменяются. Производные Parquet пишутся
в production_ml/data/, этот каталог исключён из Git.

python -m production_ml.pipeline.ingest_journals --source-root G:\lct2
python -m production_ml.pipeline.build_power_phase_v2
python -m production_ml.pipeline.train_power_phase_v2
python -m production_ml.pipeline.package_power_phase_v2
python -m production_ml.pipeline.score_active --start 2025-01-03 --end 2026-07-01 --output production_ml/data/power_phase_v2/diagnostic_scores.parquet
python -m production_ml.pipeline.create_tickets --scores production_ml/data/power_phase_v2/diagnostic_scores.parquet --output production_ml/data/power_phase_v2/diagnostic_tickets.parquet
python -m validation.check_power_phase_v2

ingest_journals принимает t, true, 1 и f, false, 0. Повторный заголовок,
неверные ключи, время и неизвестная тревога получают отдельную причину.
Точные копии полной записи удаляются. Повторный event_id с другим
содержимым сохраняется, потому что в 2021–2023 ID переиспользуются.

Признаки строятся сквозь все годы в порядке event_time, event_id,
sensor_value, is_alarm. Строка признаков относится к концу часа. Пустой
час не заменяется нормой: строки для него нет, а observed_hours_72h
показывает число часов с событиями.

Аварийные статусы: Обесточен, Неисправен, Отключено устройство.
Явное восстановление: Есть питание, Норма, Включен. Новый эпизод – переход
из последнего явного восстановления в аварийный статус. После эпизода
канал снова допускается только через 48 часов после явного восстановления.
Для обучающей метки канал должен иметь событие не раньше чем через 48
часов после точки наблюдения. Неполный будущий горизонт цензурируется.

Обучение использует 2020, 2022 и 2023 годы; январь–июнь 2024 служит
калибровкой; июль–декабрь 2024 закреплён за политикой. Период 2025–2026
остаётся диагностическим, потому что его уже просматривали в проекте.
Модель имеет фиксированный random_state 42 и фиксированные параметры из
model_meta.json. Порог 0.80 унаследован как заранее заданная политика и
не подбирался по 2025–2026.

Пакет поддерживает только «Состояние фазы». Другие типы не получают балл.
JSON в пакете проверяется по каноническому представлению, поэтому смена
LF на CRLF не меняет контрольную сумму. Модель и калибратор проверяются
по точным байтам.

score означает риск нового автоматического эпизода SCADA через 1–48
часов. Журнала ремонтов нет, поэтому это не вероятность физической
поломки и не доказательство предотвращённой аварии.

Формат заявки: ticket_id, channel_id, obs_time, score, model_version,
forecast_horizon_hours, target_kind. create_tickets обрабатывает строки
последовательно, применяет порог активной политики, лимит 10 заявок в
сутки и паузу 48 часов по каналу.
