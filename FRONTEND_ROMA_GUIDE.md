## 1. Границы ответственности и исключение размытых задач

### Что Рома ДЕЛАЕТ:
1. Разрабатывает современное одностраничное веб-приложение (SPA) на React 18 + TypeScript + Vite + Tailwind CSS.
2. Реализует дизайн-систему в строгом соответствии с брендбуком ЛЦТ 2026: шрифты Montserrat, акцентные цвета `#FF0053`, `#8A83D1`, темный фон `#1C1D22`, карточки `#252730`.
3. Верстает сводный дашборд оперативного мониторинга 16 коллекторов города Москвы с цветовой индикацией состояния.
4. Разрабатывает интерактивную топологическую схему пикетов (ПК0 – ПК1000) для каждого коллектора (векторная визуализация трассы с подсветкой аварийных участков).
5. Строит интерактивные графики временных рядов телеметрии датчиков с помощью библиотеки Recharts (отображение показаний, порогов и подсветка зон дребезга контактов).
6. Реализует модальное окно создания и верификации наряда на ремонт ТО/ППР.
7. Добавляет в шапку переключатель ролей RBAC («Диспетчер ОДС» / «Руководитель подразделения»), погодный информер Москвы и кнопку выгрузки отчетов в Excel/PDF.
8. Настраивает локальный прокси в Vite и собирает продакшн-бандл в Nginx контейнер.

### Что Рома НЕ ДЕЛАЕТ (строгие границы):
- Рома НЕ ищет реальные GPS-координаты тоннелей на картах (вместо сложной карты Leaflet/Mapbox строится наглядная топологическая мнемосхема коллектора по пикетам, аналогично схеме линий метрополитена).
- Рома НЕ парсит 15 ГБ сырых CSV в браузере (все данные запрашиваются через REST API Сани в готовом JSON-формате).
- Рома НЕ рассчитывает вероятности и признаки на клиенте (вся аналитика приходит с бэкенда).
- Рома НЕ генерирует бинарные файлы Excel и PDF на клиенте (по клику на «Экспорт» браузер скачивает готовый файл по ссылке `/api/v1/reports/...`).

## 4. Ключевые компоненты интерфейса

### 4.1. Шапка (`Header.tsx`)
- Логотипы: Проект Мэра Москвы, ДЖКХ, Лидеры цифровой трансформации 2026.
- Погодный информер: запрашивает `/api/v1/weather/current`, выводит иконку и температуру (например, `Москва: +14.2°C, 68%`).
- Переключатель роли (RBAC): `<select>` или Toggle между `Диспетчер ОДС` и `Руководитель подразделения`. При изменении передает заголовок `X-User-Role`.
- Кнопка «Экспорт отчета»: меню с кнопками `Excel (.xlsx)` и `Справка (.pdf)`. Переходит по ссылкам `/api/v1/reports/incidents.xlsx` и `/api/v1/reports/summary.pdf`.

### 4.2. Сводный дашборд (`SummaryCards.tsx` + `ObjectCard.tsx`)
- 4 ключевые плашки сверху:
  1. «Коллекторов на мониторинге»: 16;
  2. «Активных измерительных каналов»: 11 485;
  3. «Датчиков в зоне риска (ИИ-прогноз)»: динамическое число (красный бейдж);
  4. «Сформировано нарядов на ТО»: динамическое число.
- Сетка из 16 карточек коллекторов (объект Альфа, Бета, Гамма ... объект Кси). При клике на объект фокус переходит к его топологической схеме.

### 4.3. Интерактивная мнемосхема пикетов (`CollectorSchema.tsx`)
- Отображает линейный тоннель коллектора от ПК0 до ПК_max с шагом 100 м.
- Сегменты окрашены по статусу:
  - Зеленый сегмент – все датчики в норме;
  - Желтый сегмент – зафиксирован шум/флуктуации;
  - Красный сегмент – прогнозируется отказ прибора в течение 24 часов.
- При клике на пикет (например, ПК275) открывается список привязанных датчиков и кнопка перехода к графику.

### 4.4. Модуль графиков телеметрии (`TelemetryChart.tsx`)
- Построен на Recharts (`<ResponsiveContainer>`, `<LineChart>`, `<XAxis>`, `<YAxis>`, `<Tooltip>`).
- Отображает:
  - Линию показаний датчика за выбранный период (например, градусы или частота импульсов);
  - Горизонтальные опорные линии нормы (верхний и нижний порог);
  - Вертикальные маркеры зон дребезга (flapping events);
  - Прогнозную область (пунктирная линия с вероятностью выхода из строя на следующие 24 часа).

### 4.5. Модалка наряда на ремонт (`TicketModal.tsx`)
- Открывается по кнопке «Сформировать заявку на ТО» из таблицы или графика.
- Предзаполняет поля: ID датчика, пикет, наименование объекта, рекомендацию ИИ.
- Дает диспетчеру возможность выбрать приоритет, назначить бригаду и нажать «Утвердить наряд» (отправляет `POST /api/v1/tickets`).

## 5. Настройка локальной разработки без блокировок

В `frontend/vite.config.ts` настраивается прокси:
```typescript
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  server: {
    port: 3000,
    proxy: {
      '/api': {
        target: 'http://localhost:8000',
        changeOrigin: true
      }
    }
  }
});
```

Если бэкенд Сани еще не запущен, Рома может временно возвращать моковые данные прямо из `src/api/mockData.ts` (где используются структуры из [telemetry_sample_100k.csv](file:///g:/lct2/dataset/representative_slice/telemetry_sample_100k.csv)). Это дает возможность верстать без задержек.
